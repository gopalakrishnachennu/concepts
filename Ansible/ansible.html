🎯 Core Concepts

Ansible is an open-source IT automation tool that automates provisioning, configuration management, application deployment, orchestration, and many other IT processes. It's agentless, using SSH for Linux/Unix and WinRM for Windows systems.

How Ansible Works

Control Node
→
SSH/WinRM
→
Managed Nodes
🎮

Control Node

The machine where Ansible is installed. This is where you write playbooks, inventory files, and execute Ansible commands. Only one control node is needed to manage hundreds of managed nodes.

🖥️

Managed Nodes

Remote systems/servers that Ansible manages. Also called "hosts". No agent installation required - Ansible connects via SSH (Linux) or WinRM (Windows).

📋

Inventory

List of managed nodes organized in groups. Can be static (INI/YAML files) or dynamic (scripts that fetch from cloud providers like AWS, Azure, GCP).

📦

Modules

Units of code that Ansible executes. Each module has a specific purpose - managing packages, files, services, users, etc. Over 3000+ modules available.

📖

Playbooks

YAML files that describe automation jobs. They contain plays, which contain tasks. Each task calls a module to perform an action on managed nodes.

🎭

Roles

Way to organize playbooks and other files for reusability. Follows a standardized file structure with tasks, handlers, variables, templates, and files.

Ansible Execution Flow ▼
  1. Read Configuration: Ansible reads ansible.cfg for settings
  2. Parse Inventory: Loads managed hosts from inventory file
  3. Load Playbook: Reads YAML playbook and validates syntax
  4. Gather Facts: Collects system information from managed nodes
  5. Execute Tasks: Runs tasks sequentially on target hosts
  6. Module Execution: Copies Python modules to remote hosts, executes them
  7. Return Results: Collects JSON output and displays results
  8. Cleanup: Removes temporary files from managed nodes
🎯 Production Architecture Tip: In production, use separate control nodes for different environments (dev, staging, prod). Implement Git workflows for playbook version control and use Ansible Tower/AWX for centralized execution, scheduling, and RBAC (Role-Based Access Control).

🔧 Ansible Components Deep Dive

📦 Modules - The Building Blocks ▼

Modules are reusable, standalone scripts that Ansible runs on managed nodes. They are idempotent (running multiple times produces the same result) and return JSON data.

Module Categories:

System Commands Files Database Cloud Network Monitoring Web Infrastructure

Most Common Modules:

  • copy: Copy files from control to managed nodes
  • template: Process Jinja2 templates and deploy
  • file: Manage file properties (permissions, ownership)
  • yum/apt: Package management for RedHat/Debian systems
  • service: Manage system services (start, stop, restart)
  • user: Manage user accounts
  • shell/command: Execute commands (use sparingly, not idempotent)
  • git: Deploy from Git repositories
  • docker_container: Manage Docker containers
  • ec2/azure_rm: Manage cloud resources
# Module usage examples
- name: Install nginx package
  ansible.builtin.yum:
    name: nginx
    state: present

- name: Copy configuration file
  ansible.builtin.copy:
    src: /local/path/nginx.conf
    dest: /etc/nginx/nginx.conf
    owner: root
    group: root
    mode: '0644'
📖 Playbooks - Automation Scripts ▼

Playbooks are YAML files that define automation workflows. They contain one or more "plays" that map hosts to tasks. Each task calls a module with specific parameters.

Playbook Structure:

---
# Play 1: Web Server Configuration
- name: Configure Web Servers
  hosts: webservers
  become: yes
  vars:
    http_port: 80
    app_dir: /var/www/html
  
  tasks:
    - name: Install Apache
      yum:
        name: httpd
        state: present
    
    - name: Start Apache service
      service:
        name: httpd
        state: started
        enabled: yes
    
        - name: Deploy application
        copy:
          src: {{ app_dir }}/index.html
          dest: /var/www/html/
    
    handlers:
      - name: Restart Apache
        service:
          name: httpd
          state: restarted
📝 Best Practices: • Use meaningful play and task names
• Group related tasks logically
• Use variables for configuration values
• Implement error handling with blocks/rescue
• Tag tasks for selective execution
📋 Inventory - Managing Hosts ▼

Inventory defines which hosts Ansible manages and how to connect to them. Supports static (INI/YAML files) and dynamic inventory (scripts/plugins).

Static Inventory (INI Format):

# hosts.ini
  [webservers]
  web1.example.com ansible_host=192.168.1.10 ansible_user=ubuntu
  web2.example.com ansible_host=192.168.1.11 ansible_user=ubuntu
  web3.example.com ansible_host=192.168.1.12 ansible_user=ubuntu
  
  [databases]
  db1.example.com ansible_host=192.168.1.20
  db2.example.com ansible_host=192.168.1.21
  
  [loadbalancers]
  lb1.example.com ansible_host=192.168.1.30
  
  # Group variables
  [webservers:vars]
  http_port=80
  ansible_python_interpreter=/usr/bin/python3
  
  # Parent groups
  [production:children]
  webservers
  databases
  loadbalancers

Static Inventory (YAML Format):

# inventory.yml
  all:
    children:
      webservers:
        hosts:
          web1.example.com:
            ansible_host: 192.168.1.10
            http_port: 80
          web2.example.com:
            ansible_host: 192.168.1.11
        vars:
          ansible_user: ubuntu
          ansible_python_interpreter: /usr/bin/python3
      
      databases:
        hosts:
          db1.example.com:
            ansible_host: 192.168.1.20
            db_type: postgresql

Dynamic Inventory (AWS Example):

# aws_ec2.yml - Dynamic inventory plugin
  plugin: amazon.aws.aws_ec2
  regions:
    - us-east-1
    - us-west-2
  keyed_groups:
    - key: tags.Environment
      prefix: env
    - key: tags.Application
      prefix: app
  hostnames:
    - tag:Name
    - private-ip-address
🏢 Production Inventory Management: • Use dynamic inventory for cloud environments
• Organize hosts by environment (dev/staging/prod)
• Store sensitive connection info in Ansible Vault
• Use group_vars and host_vars for variable management
• Implement inventory patterns for partial deployments
🎭 Roles - Reusable Components ▼

Roles provide a framework for fully independent or interdependent collections of variables, tasks, files, templates, and modules. They promote reusability and organization.

Role Directory Structure:

roles/
  └── webserver/
      ├── tasks/
      │   └── main.yml          # Main task list
      ├── handlers/
      │   └── main.yml          # Handler definitions
      ├── templates/
      │   └── nginx.conf.j2     # Jinja2 templates
      ├── files/
      │   └── app.conf          # Static files
      ├── vars/
      │   └── main.yml          # Role variables
      ├── defaults/
      │   └── main.yml          # Default variables
      ├── meta/
      │   └── main.yml          # Role dependencies
      └── README.md             # Documentation

Role Example - Nginx Web Server:

# roles/nginx/tasks/main.yml
  ---
  - name: Install Nginx
    apt:
      name: nginx
      state: present
      update_cache: yes
  
  - name: Deploy Nginx configuration
    template:
      src: nginx.conf.j2
      dest: /etc/nginx/nginx.conf
      validate: 'nginx -t -c %s'
    notify: Restart Nginx
  
  - name: Ensure Nginx is running
    service:
      name: nginx
      state: started
      enabled: yes
  
  # roles/nginx/handlers/main.yml
  ---
  - name: Restart Nginx
    service:
      name: nginx
      state: restarted
  
  # roles/nginx/defaults/main.yml
  ---
  nginx_port: 80
  nginx_user: www-data
  nginx_worker_processes: auto

Using Roles in Playbooks:

---
  - name: Configure Web Infrastructure
    hosts: webservers
    become: yes
    
    roles:
      - common              # Base system configuration
      - role: nginx
        nginx_port: 8080  # Override default
      - security
      - monitoring
🔢 Variables - Dynamic Configuration ▼

Variables make playbooks flexible and reusable. Ansible has a well-defined variable precedence order (22 levels!) from lowest to highest priority.

Variable Precedence (Highest to Lowest):

  1. Extra vars (-e in CLI) - HIGHEST
  2. Task vars (in task itself)
  3. Block vars
  4. Role and include vars
  5. Set_facts / registered vars
  6. Play vars_files
  7. Play vars_prompt
  8. Play vars
  9. Host facts (gathered)
  10. Playbook host_vars
  11. Playbook group_vars
  12. Inventory host_vars
  13. Inventory group_vars
  14. Role defaults - LOWEST

Variable Definition Examples:

# In playbook
  - name: Deploy Application
    hosts: webservers
    vars:
      app_name: myapp
      app_version: "1.2.3"
      app_config:
        port: 8080
        timeout: 30
    
    vars_files:
      - vars/common.yml
      - vars/{{ ansible_os_family }}.yml
    
    tasks:
      - name: Register variable from command
        command: cat /etc/hostname
        register: hostname_output
      
      - name: Set fact
        set_fact:
          custom_var: "{{ hostname_output.stdout }}"
      
      - name: Debug variables
        debug:
          msg: "App {{ app_name }} v{{ app_version }} on {{ custom_var }}"

Magic Variables (Automatically Available):

  • hostvars: Access variables of other hosts
  • groups: List of all groups in inventory
  • group_names: Groups current host belongs to
  • inventory_hostname: Name of current host
  • ansible_facts: Gathered system information
  • playbook_dir: Directory of current playbook
  • role_path: Path to current role
# Using magic variables
  - name: Configure cluster
    debug:
      msg: "DB Host: {{ hostvars['db1.example.com']['ansible_host'] }}"
  
  - name: Get all web servers
    debug:
      msg: "Web servers: {{ groups['webservers'] }}"
⚡ Handlers - Event-Driven Tasks ▼

Handlers are special tasks that run only when notified by other tasks. They run once at the end of a play, even if notified multiple times. Perfect for service restarts after config changes. 

---
  - name: Web Server Configuration
    hosts: webservers
    become: yes
    
    tasks:
      - name: Update Nginx config
        template:
          src: nginx.conf.j2
          dest: /etc/nginx/nginx.conf
        notify:
          - Validate Nginx config
          - Restart Nginx
      
      - name: Update SSL certificate
        copy:
          src: "{{ item }}"
          dest: /etc/nginx/ssl/
        loop:
          - server.crt
          - server.key
        notify: Restart Nginx
    
    handlers:
      - name: Validate Nginx config
        command: nginx -t
        changed_when: false
      
      - name: Restart Nginx
        service:
          name: nginx
          state: restarted
        listen: "restart web services"
      
      - name: Reload Nginx
        service:
          name: nginx
          state: reloaded
⚙️ Handler Best Practices: • Use meaningful handler names
• Group related handlers with "listen" directive
• Handlers run in order they're defined, not notified
• Use meta: flush_handlers to run handlers immediately
• Handlers don't run if playbook fails (use force_handlers: true)
🔐 Ansible Vault - Secrets Management ▼

Ansible Vault encrypts sensitive data like passwords, API keys, and certificates. Files are encrypted with AES256. You can encrypt entire files or specific variables.

Vault Commands:

# Create encrypted file
  ansible-vault create secrets.yml
  
  # Encrypt existing file
  ansible-vault encrypt vars/passwords.yml
  
  # Edit encrypted file
  ansible-vault edit secrets.yml
  
  # Decrypt file
  ansible-vault decrypt secrets.yml
  
  # View encrypted file
  ansible-vault view secrets.yml
  
  # Change vault password
  ansible-vault rekey secrets.yml
  
  # Encrypt string (for inline vars)
  ansible-vault encrypt_string 'mypassword' --name 'db_password'

Using Vault in Playbooks:

# secrets.yml (encrypted)
  db_password: supersecretpassword
  api_key: "abc123xyz789"
  aws_access_key: AKIAIOSFODNN7EXAMPLE
  
  # playbook.yml
  ---
  - name: Deploy with secrets
    hosts: databases
    vars_files:
      - secrets.yml
    
    tasks:
      - name: Configure database
        postgresql_user:
          name: appuser
          password: "{{ db_password }}"
  
  # Run with vault password
  # ansible-playbook playbook.yml --ask-vault-pass
  # ansible-playbook playbook.yml --vault-password-file ~/.vault_pass

Ensure playbooks can run multiple times safely without causing unintended changes. 

# Bad - Not idempotent
  - command: echo "config" >> /etc/app.conf
  
  # Good - Idempotent
  - lineinfile:

☁️ Example 3: AWS Infrastructure Provisioning ▼ 
---
  - name: Provision AWS Infrastructure
    hosts: localhost
    gather_facts: no
    vars:
      region: us-east-1
      vpc_cidr: "10.0.0.0/16"
    
    tasks:
      - name: Create VPC
        amazon.aws.ec2_vpc_net:
          name: production-vpc
          cidr_block: "{{ vpc_cidr }}"
          region: "{{ region }}"
          tags:
            Environment: Production
        register: vpc
      
      - name: Create subnet
        amazon.aws.ec2_vpc_subnet:
          vpc_id: "{{ vpc.vpc.id }}"
          cidr: "10.0.1.0/24"
          az: "{{ region }}a"
          tags:
            Name: web-subnet
        register: subnet
      
      - name: Create security group
        amazon.aws.ec2_security_group:
          name: web-sg
          description: Web server security group
          vpc_id: "{{ vpc.vpc.id }}"
          rules:
            - proto: tcp
              ports: 80
              cidr_ip: 0.0.0.0/0
            - proto: tcp
              ports: 443
              cidr_ip: 0.0.0.0/0
      
      - name: Launch EC2 instances
        amazon.aws.ec2_instance:
          name: "web-{{ item }}"
          instance_type: t2.micro
          image_id: ami-0c55b159cbfafe1f0
          vpc_subnet_id: "{{ subnet.subnet.id }}"
          count: 3
          tags:
            Environment: Production
            Role: WebServer
        loop: "{{ range(1, 4) | list }}"
🔄 Example 4: Zero-Downtime Rolling Deployment ▼ 
---
  - name: Rolling Update with Zero Downtime
    hosts: webservers
    serial: 1  # Update one server at a time
    max_fail_percentage: 0
    
    tasks:
      - name: Remove from load balancer
        community.general.haproxy:
          state: disabled
          host: "{{ inventory_hostname }}"
          backend: web_backend
        delegate_to: load_balancer
      
      - name: Wait for connections to drain
        wait_for:
          timeout: 30
      
      - name: Stop application
        service:
          name: myapp
          state: stopped
      
      - name: Backup current version
        archive:
          path: /opt/myapp
          dest: "/backup/myapp-{{ ansible_date_time.iso8601 }}.tar.gz"
      
      - name: Deploy new version
        unarchive:
          src: releases/myapp-v2.0.tar.gz
          dest: /opt/myapp
          remote_src: no
      
      - name: Run database migrations
        command: /opt/myapp/bin/migrate
        run_once: yes
      
      - name: Start application
        service:
          name: myapp
          state: started
      
      - name: Wait for app to be ready
        uri:
          url: "http://localhost:8080/health"
          status_code: 200
        register: result
        until: result.status == 200
        retries: 10
        delay: 5
      
      - name: Add back to load balancer
        community.general.haproxy:
          state: enabled
          host: "{{ inventory_hostname }}"
          backend: web_backend
        delegate_to: load_balancer
      
      - name: Smoke test
        uri:
          url: "http://{{ inventory_hostname }}/api/test"
          return_content: yes
        register: test_result
        failed_when: "'success' not in test_result.content"

🎓 Advanced Ansible Concepts

🔁 Loops & Conditionals ▼

Different Loop Types:

# Simple loop
  - name: Install packages
    yum:
      name: "{{ item }}"
      state: present
    loop:
      - httpd
      - nginx
      - postgresql
  
  # Loop with dictionary
  - name: Create users
    user:
      name: "{{ item.name }}"
      uid: "{{ item.uid }}"
      shell: "{{ item.shell }}"
    loop:
      - { name: 'alice', uid: 1001, shell: '/bin/bash' }
      - { name: 'bob', uid: 1002, shell: '/bin/zsh' }
  
  # Loop with index
  - name: Process items with index
    debug:
      msg: "Item {{ item.0 }}: {{ item.1 }}"
    loop: "{{ my_list | zip_longest(['a','b','c']) | list }}"
  
  # Loop until condition
  - name: Wait for service
    shell: systemctl is-active myservice
    register: result
    until: result.rc == 0
    retries: 5
    delay: 10
  
  # Nested loops
  - name: Create directory structure
    file:
      path: "/data/{{ item.0 }}/{{ item.1 }}"
      state: directory
    loop: "{{ users | product(folders) | list }}"
  
  # Conditionals
  - name: Install on RedHat only
    yum:
      name: httpd
    when: ansible_os_family == "RedHat"
  
  - name: Multiple conditions
    debug:
      msg: "Valid system"
    when:
      - ansible_distribution == "CentOS"
      - ansible_distribution_major_version == "7"
      - ansible_memtotal_mb >= 2048
🎨 Jinja2 Templates ▼

Jinja2 is the templating engine used by Ansible for dynamic file generation. 

{# nginx.conf.j2 template #}
  user {{ nginx_user }};
  worker_processes {{ nginx_worker_processes | default('auto') }};
  
  events {
      worker_connections {{ nginx_worker_connections | default(1024) }};
  }
  
  http {
      {% if enable_gzip %}
      gzip on;
      gzip_types text/plain text/css application/json;
      {% endif %}
      
      {% for server in web_servers %}
      upstream backend_{{ server.name }} {
          {% for host in server.hosts %}
          server {{ host.ip }}:{{ host.port }} weight={{ host.weight | default(1) }};
          {% endfor %}
      }
      {% endfor %}
      
      server {
          listen {{ http_port }};
          server_name {{ server_name }};
          
          {% if ssl_enabled %}
          listen 443 ssl;
          ssl_certificate {{ ssl_cert_path }};
          ssl_certificate_key {{ ssl_key_path }};
          {% endif %}
          
          location / {
              proxy_pass http://backend_{{ app_name }};
              proxy_set_header Host $host;
              proxy_set_header X-Real-IP $remote_addr;
          }
      }
  }

Jinja2 Filters:

# String filters
  "{{ variable | upper }}"          # UPPERCASE
  "{{ variable | lower }}"          # lowercase
  "{{ variable | capitalize }}"     # Capitalize
  "{{ variable | replace('old', 'new') }}"
  
  # List filters
  "{{ list | length }}"             # Count items
  "{{ list | first }}"              # First item
  "{{ list | last }}"               # Last item
  "{{ list | unique }}"             # Remove duplicates
  "{{ list | sort }}"               # Sort list
  "{{ list | join(', ') }}"         # Join with delimiter
  
  # Math filters
  "{{ number | int }}"              # Convert to integer
  "{{ number | round }}"            # Round number
  "{{ number | abs }}"              # Absolute value

🔌 Callback Plugins & Ansible Tower ▼

Callback plugins allow you to hook into Ansible events and customize output or integrate with external systems. 

# callback_plugins/custom_logger.py
  from ansible.plugins.callback import CallbackBase
  import json
  import logging
  
  class CallbackModule(CallbackBase):
      CALLBACK_VERSION = 2.0
      CALLBACK_TYPE = 'notification'
      CALLBACK_NAME = 'custom_logger'
      
      def __init__(self):
          super(CallbackModule, self).__init__()
          logging.basicConfig(filename='ansible.log', level=logging.INFO)
      
      def v2_runner_on_ok(self, result):
          host = result._host.name
          logging.info(f"SUCCESS: {host} - {result._task.name}")
      
      def v2_runner_on_failed(self, result, ignore_errors=False):
          host = result._host.name
          logging.error(f"FAILED: {host} - {result._task.name}")
          logging.error(f"Error: {result._result}")

🚀 Optimization Techniques ▼

Ansible Configuration for Performance:

# ansible.cfg - Performance tuning
                        [defaults]
                        forks = 50                          # Parallel execution (default: 5)
                        gathering = smart                   # Cache facts
                        fact_caching = jsonfile
                        fact_caching_connection = /tmp/ansible_facts
                        fact_caching_timeout = 86400        # 24 hours
                        
                        pipelining = True                   # Reduce SSH operations
                        
                        [ssh_connection]
                        ssh_args = -o ControlMaster=auto -o ControlPersist=60s
                        control_path = /tmp/ansible-ssh-%%h-%%p-%%r
                        pipelining = True

Playbook Optimization Strategies:

# Disable fact gathering when not needed
                        - name: Quick task without facts
                          hosts: all
                          gather_facts: no
                          tasks:
                            - debug: msg: "Fast execution"
                      
                        # Gather subset of facts only
                        - name: Minimal facts
                          hosts: all
                          gather_facts: yes
                          gather_subset:
                            - '!all'
                            - '!min'
                            - network
                            - virtual
                      
                        # Use async for long-running tasks
                        - name: Long running task
                          command: /usr/bin/long_script.sh
                          async: 3600
                          poll: 0
                          register: long_task
                      
                        - name: Check async task status
                          async_status:
                            jid: "{{ long_task.ansible_job_id }}"
                          register: job_result
                          until: job_result.finished
                          retries: 30
                      
                        # Batch operations instead of loops
                        - name: Install multiple packages (efficient)
                          yum:
                            name:
                              - httpd
                              - nginx
                              - postgresql
                            state: present
                      
                        # Use strategy plugins
                        - name: Free strategy (don't wait for all hosts)
                          hosts: all
                          strategy: free
                          tasks:
                            - name: Independent tasks
                              shell: process_data.sh
💡 Performance Best Practices:
• Use fact caching to avoid re-gathering
• Enable pipelining to reduce SSH overhead
• Increase forks for large inventories
• Use async for long-running operations
• Batch package installations
• Use strategy plugins appropriately
• Profile playbooks with callback plugins

🔧 Troubleshooting Guide

Common Issues

SSH Connection Failed:
• Check SSH keys and permissions
• Verify host in known_hosts
• Test: ssh user@host

Module Not Found:
• Install collection: ansible-galaxy collection install
• Check ANSIBLE_LIBRARY path

Permission Denied:
• Use become: yes
• Check sudo configuration
• Verify user permissions

Performance Issues

Slow Execution:
• Increase forks in ansible.cfg
• Enable fact caching
• Use pipelining
• Disable fact gathering if not needed

Timeout Errors:
• Increase timeout in ansible.cfg
• Use async for long tasks
• Check network connectivity
