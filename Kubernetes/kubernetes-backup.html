🧩 Core Kubernetes Components

🧱 Pod - The Basic Unit

Smallest deployable unit in Kubernetes. A pod can contain one or more containers that share network and storage resources.

apiVersion: v1 kind: Pod metadata: name: nginx-pod spec: containers: - name: nginx image: nginx:latest ports: - containerPort: 80
Component Purpose Use Case
Pod Smallest deployable unit Running single or multiple containers together
ReplicaSet Maintains stable set of replica Pods Ensuring 3 copies of your app are always running
Deployment Declarative updates for Pods and ReplicaSets Rolling updates, rollbacks, scaling
Service Stable network endpoint Load balancing, service discovery
StatefulSet Manages stateful applications Databases, message queues
DaemonSet Runs on all/selected nodes Logging agents, monitoring tools
Job/CronJob Run-to-completion tasks Batch processing, scheduled tasks

🔄 The Reconciliation Loop

Kubernetes continuously monitors the desired state (what you want) vs actual state (what exists) and takes action to reconcile differences.

Control Loop Pattern: while true: desired_state = etcd.get("/desired") actual_state = cluster.observe() if actual_state != desired_state: take_action_to_reconcile() sleep(reconciliation_interval)
